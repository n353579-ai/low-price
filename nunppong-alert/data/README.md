# 단속카메라 데이터

앱에 들어 있는 `app/src/main/assets/cameras.grid.txt` 는 공공데이터포털
**전국무인교통단속카메라표준데이터**(경찰청, https://www.data.go.kr/data/15028200/standard.do)를
`tools/convert_cameras.py` 로 변환한 것입니다. 원본 이용 조건은 해당 데이터셋 페이지를 따릅니다.

## 자동 갱신
`.github/workflows/update-cameras.yml` 이 매월 오픈API(`tools/fetch_cameras.py`)로 최신 데이터를 받아
변환·커밋합니다. 인증키는 저장소 Secret `DATA_GO_KR_KEY` 에만 있습니다.
새 데이터가 기존의 90% 미만이거나 일부만 받아지면 기존 파일을 그대로 둡니다.
(봇 커밋은 APK 빌드를 자동으로 시작하지 않으므로, 필요하면 Actions에서 빌드를 직접 돌리거나 아무 변경이나 푸시하세요.)

## 수동 갱신
이 폴더(`nunppong-alert/data/`)에 CSV를 올리면 빌드 때 자동 변환됩니다.

변환 규칙: 제한속도가 있는 행을 과속 단속으로 보고(주정차 전용 제외), 좌표 없는 행과 같은 위치 중복을 제거합니다.
방향각 컬럼은 없고, `roadRouteDrc` 는 1/2/3 코드라 쓰지 않습니다.

## 도로 선 (오탐 줄이기)
앱은 지도를 넣지 않고, 카메라마다 **카메라 앞 약 1.1km 의 도로 선**만 가집니다(`cameras.grid.txt` 의 `P` 줄).
`tools/build_paths.py <한국.osm.pbf>` 가 OpenStreetMap(Geofabrik 한국 추출본)에서 뽑아 붙입니다. 자동 갱신 워크플로가 매월 같이 실행합니다.
- 내가 그 선 위(옆 30m 이내)를 카메라 쪽으로 달릴 때만 1km 앞부터 알립니다. 남은 거리는 도로를 따라 잽니다.
- 선과 안 맞아도 100m 안 바로 정면이면 알립니다(도로 정보가 틀렸을 때의 마지막 안전망).
- 상·하행이 따로 그려진 도로의 카메라는 방향각이 확정되어 반대 차선에서 울리지 않습니다.
- `P` 줄이 없는 카메라(근처 도로 없음)는 예전 방식(진행방향 ±30°)으로 판단합니다.
- 수동 CSV 갱신을 하면 `P` 줄이 사라지므로 `build_paths.py` 를 다시 돌려야 합니다(안 돌리면 테스트 `RealDataPathTest` 가 실패해 알려 줍니다).

도로 정보 © OpenStreetMap contributors (ODbL). 앱 화면에도 표시합니다.

## 반대 차선 줄이기 (방향 근거)
카메라가 '어느 방향 차량을 단속하는지'는 공공데이터에 칸이 없어서 세 가지 근거로 추정합니다(`build_paths.py`).
1. 상·하행이 따로 그려진 도로 → 확정(방향각 기록)
2. 카메라가 도로 한쪽 옆 10m 이상에 서 있음 → 약 96% 일치(검증)
3. 설치장소 글자 `A→B`의 도착지·출발지 이름을 OSM 지점 이름에서 찾아 방향 계산(`--csv=원본.csv` 필요)
- 2와 3이 같은 방향이면 방향각을 기록합니다(검증 정확도 99%, 161건 중 160건).
- 근거가 하나뿐이면 방향각은 쓰지 않고, 반대쪽 접근 경로를 `Q` 줄(카메라 앞 200m 안에서만 알림)로 둡니다. 추정이 틀려도 200m 안에서는 알립니다.
- 모르면 양쪽 모두 `P` 줄(1km 앞부터)입니다.

## 꺾을 수 있는 교차로 (J 줄)
`P`/`Q` 줄 바로 뒤의 `J` 줄은 그 경로 위에서 내가 꺾어 나갈 수 있는 교차로까지의 "카메라까지 남은 거리(m)"입니다.
목적지를 모르는 앱이라, 카메라 앞에 꺾을 수 있는 교차로가 2개 이상 남은 동안은 알림을 미룹니다(150m 안이면 무조건 알림).
실제 도로 1,560km 가상 주행(`tools/make_test_routes.py` + `RouteFalseAlertTest`)으로 값을 골랐습니다: 틀린 알림 -20%, 정답 알림 -2%.

## 알림 거리 (속도 기준)
알림은 카메라 앞 "지금 속도로 약 30초" 지점부터 시작합니다 (속도 m/s × 30m, 150~1000m).
빠를수록 멀리서, 막혀서 기어가면 가까이서 알립니다. 범위의 60% 안은 2단계, 30% 안(약 9초 전)은 3단계입니다.
멈춰서 8초가 지났고 카메라가 200m보다 멀면 알림을 끕니다(카메라 바로 앞 신호 대기는 90초까지 유지).
가상 주행 시나리오 측정: `tools/make_test_routes.py` 로 도로 종류별 경로를 만들고(`--limit-min/--limit-max`),
`ROUTES_FILES="이름=경로파일,..." ./gradlew testDebugUnitTest --tests '*RouteFalseAlertTest*' -i` 로 속도·정체 시나리오별 표를 본다.

## 방향 근거 3종 (build_paths.py)
1. 길가 위치(side): 도로 한쪽 옆 10m 이상 (약 96%)
2. 설치장소 글자 `A→B` (이름 매칭, 약 93%)
3. 쌍 위치(pair): 40m 안의 카메라 쌍에서 각 카메라는 자기 방향의 오른쪽 길가에 선다. 간격 20m 이상이면 97%, 5~12m는 72~75%라 단독으로는 확정하지 않는다.
- **서로 다른 근거 2개가 같은 방향이면 확정**(방향각 기록): 길가+쌍 87건 중 87건 일치. 쌍이 20m 이상 벌어졌을 때만 단독 확정.
- 근거가 하나뿐이면 반대쪽 접근 경로를 `Q`(약한 경로)로 두고 속도 x 4초(50~150m) 안에서만 알린다.
